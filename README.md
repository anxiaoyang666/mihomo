# Mihomo Toolbox

[English](README.md) | [中文](README.zh-CN.md)

Mihomo Web panel and helper scripts for a gateway-style Mihomo service.

## One-Click Install

Run as `root` on Debian/Ubuntu LXC, VM, or server:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/anxiaoyang666/mihomo/main/install.sh)"
```

China network acceleration:

```bash
bash -c "$(curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/anxiaoyang666/mihomo/main/install.sh)"
```

The installer prints the Web panel address, username, and password when it finishes. The default Web port is `7838`, and the default username is `admin`.

Custom install parameters:

```bash
WEB_PORT=7838 WEB_USER=admin WEB_SECRET='your-password' bash -c "$(curl -fsSL https://raw.githubusercontent.com/anxiaoyang666/mihomo/main/install.sh)"
```

Available variables:

- `MIHOMO_REPO_URL`: repository URL, default `https://github.com/anxiaoyang666/mihomo.git`
- `MIHOMO_BRANCH`: install branch, default `main`
- `WEB_PORT`: Web panel port, default `7838`
- `WEB_HOST`: address the panel binds to, default `0.0.0.0` (unchanged, so an existing LAN install stays reachable). Set `127.0.0.1` to accept local connections only.
- `WEB_USER`: Web login username, default `admin`
- `WEB_SECRET`: Web login password, randomly generated when omitted. The panel stores a salted hash (Werkzeug scrypt, or pbkdf2). A plaintext value already in `.env` is hashed on startup. If hashing fails, the plaintext password still works.
- `WEB_COOKIE_SECURE`: `true` or `false`, default `false`. See the TLS note below.
- `GH_PROXY`: GitHub proxy prefix, default `https://gh-proxy.com/`
- `GH_PROXY_BINARIES`: `true` to let the mihomo-core download fall back to `GH_PROXY`. Default `false`. The proxy is never used for the asset digest.
- `MIHOMO_KEEP_ENV`: keep existing `/etc/mihomo/.env`, default `1`

## Online Panel Upgrade

New panel versions can upgrade themselves from this repository. The panel reads these optional values from `/etc/mihomo/.env`:

```bash
MIHOMO_PANEL_REPO_URL="https://github.com/anxiaoyang666/mihomo.git"
MIHOMO_PANEL_BRANCH="main"
# GitHub is always tried directly first; GH_PROXY is only a fallback (empty = no proxy)
GH_PROXY="https://gh-proxy.com/"
```

Other optional `.env` keys:

- `GH_PROXY`: GitHub proxy prefix used only as a fallback after a direct GitHub download fails (empty = no proxy). Panel source may use it, but only after the commit is pinned from `api.github.com` and the archive matches that commit's git tree.
- `GH_PROXY_BINARIES`: set to `true` to allow that same prefix for the mihomo core binary. Default `false`. A proxied binary is installed only when its size and `sha256` match the release asset from `api.github.com` fetched directly. With no digest, a proxied binary is refused; a direct GitHub download still falls back to a gzip integrity check.
- `WEB_HOST`: listen address, default `0.0.0.0`. Changing it needs a restart of `mihomo-manager`.
- `WEB_COOKIE_SECURE`: `true` sends the session cookie with the Secure flag. Default `false`.
- `MIHOMO_API_SECRET`: `external-controller` secret, generated by `install.sh` and written to both `config.yaml` and `.env` (the panel and the external Dashboard on port 9090 both use it)
- `BACKUP_KEEP_COUNT`: how many `config.yaml` backups to keep, default `10`
- `ALLOW_INSECURE_TLS=true`: skip TLS certificate checks when downloading subscriptions / Geo data (off by default)
- `GATEWAY_AUTOFIX=false`: stop the per-minute `gateway_init.sh check` cron job from re-applying ip_forward / rp_filter / FORWARD / MASQUERADE (default `true`; running the script by hand still applies them)
- `RULE_SYNC_ENABLED`: `true` to push the panel's force-direct / force-proxy rules to other mosctl / mihomo panels (default `false`)
- `RULE_SYNC_TOKEN`: shared secret for rule sync; generated by `install.sh`, must match on every peer
- `RULE_SYNC_PEERS`: peer panel URLs separated by `|` (the panel's sync settings page writes this)

TLS: the panel is Flask's HTTP development server and does not terminate TLS. `SESSION_COOKIE_SECURE` stays off unless `WEB_COOKIE_SECURE=true`, because browsers drop Secure cookies on plain `http://` and you would not stay logged in. Set `WEB_COOKIE_SECURE=true` only when every browser reaches the panel through HTTPS (a reverse proxy you operate). The panel process still speaks HTTP to that proxy. Leave the default alone on a LAN HTTP install.

The panel also writes `WEB_PASSWORD_STRONG` (`true` or `false`) when it hashes a password, so the security page can still warn about a short or all-digit password after the plaintext is gone. Do not edit that flag by hand.

Panel upgrades preserve local runtime state:

- `/etc/mihomo/.env`
- `/etc/mihomo/config.yaml`
- `/etc/mihomo/ui`

## One-Time Upgrade For Old Panels

Old installations that do not yet have the online upgrade button can be upgraded once over SSH:

```bash
bash -c 'set -e; TMP=$(mktemp -d); mkdir -p /etc/mihomo/backup; curl -fL -o "$TMP/mihomo.zip" "https://gh-proxy.com/https://github.com/anxiaoyang666/mihomo/archive/refs/heads/main.zip"; python3 - <<PY "$TMP/mihomo.zip" "$TMP"
import sys, zipfile
zipfile.ZipFile(sys.argv[1]).extractall(sys.argv[2])
PY
SRC=$(find "$TMP" -maxdepth 3 -type d -name remote-root | head -n1); test -n "$SRC"; BACKUP="/etc/mihomo/backup/manager.before-upgrade.$(date +%Y%m%d%H%M%S)"; [ -d /etc/mihomo/manager ] && cp -a /etc/mihomo/manager "$BACKUP" || true; install -m 0755 "$SRC/usr/bin/mihomo" /usr/bin/mihomo; rm -rf /etc/mihomo/manager /etc/mihomo/scripts /etc/mihomo/templates; mkdir -p /etc/mihomo/manager /etc/mihomo/scripts /etc/mihomo/templates; cp -a "$SRC/etc/mihomo/manager/." /etc/mihomo/manager/; cp -a "$SRC/etc/mihomo/scripts/." /etc/mihomo/scripts/; cp -a "$SRC/etc/mihomo/templates/." /etc/mihomo/templates/; install -m 0644 "$SRC/etc/systemd/system/mihomo.service" /etc/systemd/system/mihomo.service; install -m 0644 "$SRC/etc/systemd/system/mihomo-manager.service" /etc/systemd/system/mihomo-manager.service; install -m 0644 "$SRC/etc/systemd/system/force-ip-forward.service" /etc/systemd/system/force-ip-forward.service; install -m 0644 "$SRC/etc/mihomo/config.example.yaml" /etc/mihomo/config.example.yaml; mkdir -p /etc/logrotate.d; install -m 0644 "$SRC/etc/logrotate.d/mihomo" /etc/logrotate.d/mihomo; systemctl daemon-reload; systemctl restart mihomo-manager; rm -rf "$TMP"; echo "Mihomo panel upgraded. Backup: $BACKUP"'
```

Run the command inside the host/container where `/etc/mihomo` and `mihomo-manager` are installed. It replaces the same files the panel's online upgrade manages: `/usr/bin/mihomo`, `manager/`, `scripts/`, `templates/`, `config.example.yaml`, the three systemd units and `/etc/logrotate.d/mihomo`; `.env`, `config.yaml` and `ui/` are left alone.

## Layout

- `remote-root/`: files copied into their absolute locations on install/upgrade.
- `tests/`: contract tests for panel upgrade behavior.

## Local Files Not Published

The repository intentionally ignores live secrets, subscriptions, provider cache, runtime config, extraction inventory, and archives.
